# Post-release backlog

## Release gates, not deferred feature work

Owner UX acceptance and explicit publication approval; source copyright/license
choice; Microsoft/runtime redistribution review; final portable integrity/smoke
checks and any unavailable manual GUI verification. No item is silently waived
because other tests pass. No repository/release is published automatically.

## Acceptable later improvements

- Broaden supported original-target references only with reviewed evidence.
- Improve deterministic suggestions for ambiguous/multi-component addons; keep
  useful component descriptions. Do not chase a suggestion-count target.
- Evaluate description-based inference with ambiguity/credits/hostile-text tests.
- Tranche metadata work beyond the current 200-due-item action cap.
- Expand Windows/Steam/locale/device beta coverage and native-link/VPK v2 cases.
- Investigate exact engine path comparison and load-order behavior from credible
  observations; keep static overlap separate from runtime compatibility.
- Consider properly sourced runtime incident storage only with a separately
  approved design; no speculative crash percentage.

M7/Game Active, addonlist/enabled-state editing, remote VPK downloading,
subscription management, multiple Planning sets and load-order tools require
separate authorization. This backlog is not approval to implement them.
